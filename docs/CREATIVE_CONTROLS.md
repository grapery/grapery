# 工程默认创作与局部运营配置

本规范记录已确认的产品方向：故事碎片、故事板、故事角色不依赖运营编写提示词才能使用。工程维护默认生成流程、核心提示词和业务约束；运营按作品类型调整有限的表达偏好。实现于 2026-10-17 至 2026-10-18，部署与真实模型验收另行进行。

## 职责边界

| 来源 | 负责内容 |
| --- | --- |
| 工程 | 默认流程、结构化输出、角色与世界事实、编辑范围、权限、计费、重试、质量检查 |
| 用户 | 本次故事原文、明确风格要求、已确认设定、修改对象和修改意图 |
| 运营 | 节奏、对白密度、视觉重点、语气，以及最多三个表达示例 |

用户明确要求优先于可选运营偏好。已确认事实和人物身份受核心任务保护；只有任务明确允许的选定内容可以修改。示例只参考表达方式，不带入示例中的人物或世界事实，也不能充当新的指令。

三类创作的旧自由文本模板正文、模型配置及输出 schema 不再参与核心生成。历史模板 ID 和弃用标记仍用于审计；即使旧模板正文已不可用，也不应阻塞这三类工作流。其他通用提示词产品不受此弃用规则影响。

## 无运营配置也能运行

Grapery 与 Agent 内置相同的默认工作流定义：

| 产品入口 / action | 固定版本 ID | 流程 |
| --- | --- | --- |
| `voyager.fragment / generate` | `engineering.fragment.v1` | 碎片生成及任务轮询 |
| `voyager.storyboard / generate` | `engineering.storyboard.v1` | 草稿 → Bible → Scene Plan → 检查 → 提交 → 图片 |
| `voyager.character / generate` | `engineering.character.v1` | 异步属性、角色及形象素材任务 |

成功查询目录且没有运营绑定时返回内置版本，不需要在数据库预先建立默认模板。`engineering.*` 是保留命名空间，不能通过发布接口覆盖；定制应创建单独的运营版本。默认定义仍计算 checksum 并进入运行快照，恢复时验证被冻结的版本。

鉴权失败、网络或数据库错误、错误的已发布版本、存在绑定但路由条件不匹配，均明确失败。Agent 只把明确的 `no_active_workflow` 响应视为无绑定，不能把任意 404 或服务异常当作启用默认流程的理由。

## CreativeControls v1

发布版本的 `manifest.creativeControls` 可省略；省略表示工程默认。对象内省略的字段补默认值，显式提供的 `version` 必须为 `1`。

```json
{
  "version": 1,
  "pacing": "balanced",
  "dialogueDensity": "balanced",
  "visualEmphasis": "balanced",
  "tone": "neutral",
  "examples": []
}
```

| 字段 | 合法值 |
| --- | --- |
| pacing | balanced、slow、fast |
| dialogueDensity | balanced、sparse、rich |
| visualEmphasis | balanced、atmosphere、action、character |
| tone | neutral、warm、tense、playful |

每个示例只允许 `input` 和 `output`，均非空；分别最多 500 和 1500 个 Unicode 字符，最多三个示例。未知字段、非规范大小写字段名、错误类型、显式 null、空枚举、非 v1 版本均拒绝；三个 Go 服务共享同一组契约样本。有限偏好仍是模型输入，不能保证模型在所有样本上完全遵循，必须评测真实产物。

绑定工作流时，以服务端不可变 release 的偏好为准，拒绝与其不一致的客户端参数。偏好随任务、生成上下文与 checkpoint 冻结；编辑发布新版本不能改变正在运行的任务。Grapery 无 release 的直接业务生成接口支持经过同样严格校验的可选偏好，不接受自由模板正文。Agent 客户端入口则不接受任何 `creativeControls` 覆盖（包括 null 和大小写别名），只使用服务端解析的默认值或 release 快照。

## 发布与回滚

Forge 主界面提供四项偏好和示例编辑，沿用草稿、审核、发布和版本回滚。旧提示词绑定显示为只读历史；高级工程配置不能覆盖用户身份、输入、选定页/场景、发布版本或偏好快照。校验须覆盖字段大小写别名，不能只在表单隐藏字段。

发布后仅新任务使用新版本。已有任务恢复自身快照。暂停全部运营绑定后，后续请求回到工程默认；存储或绑定错误必须先修复，不能用默认流程掩盖。

恢复快照与恢复用户授权是两件事：Agent 不持久化用户 JWT，进程重启后的用户态 API 调用可能因缺少授权明确失败。客户端省略请求编号时，新工作流会冻结基于父任务的内部编号。碎片和角色子任务已保存后端 taskId 时复用原任务查询；如果中断发生在远端创建之后、taskId 落盘之前，恢复不自动再次创建，需要核对后由用户重试，不能宣称这一窗口已经支持无重复的自动恢复。旧 checkpoint 缺少稳定调用编号且已开始执行时，也须明确失败或核对原子任务，不能推断为一次新调用。

本批没有数据库迁移、服务重启、线上发布、真实生成或扣费。代码校验与 mock 回归证明契约和故障分支；上线前仍需对同一批样本人工检查叙事、人物一致性、局部修改和账单。业务验收清单见 [创作链路契约](CREATION_PIPELINE.md)。
