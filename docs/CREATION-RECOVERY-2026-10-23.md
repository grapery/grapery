# 碎片恢复与故事板修改幂等修复

## 碎片生成

服务启动后立即扫描可恢复任务，之后每 15 秒扫描一次。每个进程最多执行四个任务；数据库领取租约后才能执行，租约有效期两分钟，每 20 秒续期。任务、检查点、图片槽位和草稿提交验证 owner、fence 与有效期；取消和任务接管后，旧执行者不能覆盖新状态。

新任务保存执行版本与 ready 标记，只有草稿准备完成后才入队，避免扫描器抢先执行。准备超过五分钟仍未入队的任务明确标为失败，不会调用模型；老任务通过版本零兼容处理。

任务内部保存版本化阶段检查点，冻结原草稿和续写上下文。已完成的元素提取、场景扩展、逐页规划、参考素材、出图与审核复用已保存结果。图片使用稳定操作 ID，复用已有输出和结算记录；未知供应商结果不盲目重发。草稿提交前持久化完整候选结果，恢复重复提交同一候选，防止续写重复追加图片。

客户端重试只调用原任务的 `POST /fragments/generate/:taskId/retry`，随后以返回的同一 task ID 直接轮询碎片状态。旧的失败 Agent run 会解除绑定，状态查询失败时保留原任务身份和已生成内容，不会回退为新的 create/append 请求。服务端以用户和 clientMessageID 生成稳定任务主键，并校验完整请求意图；同键不同意图返回冲突。

没有检查点的历史处理中任务，或不具备可确定恢复条件的模型调用窗口，会明确失败并保留已存结果，不再永久保持 processing。此行为避免重复付费，但不宣称供应商结果未知时也能自动完成。进程退出后须等原租约到期才可接管。

## 故事板修改

修改请求保存版本化意图，包含目标 scene ID 集合、原请求 baseRevision、修改指令、有效场景数、语言、风格、偏好及故事板上下文。目标 ID 排序、去重后比较。相同请求编号必须对应相同意图；改变意图返回冲突，不能静默恢复第一次请求。

重试会查询对应故事板、用户和请求编号的历史记录，不再只检查 latest。显式 generationRunId 的阶段续跑继续使用冻结数据；调用方补充的修改参数必须与原任务一致。旧记录缺少足以证明意图相同的信息时，保守拒绝有歧义的重试。

故事板图片任务保存 owner、内容版本和尝试顺序。供应商输出先写入唯一 generation ID 对应的候选对象，再通过事务校验当前 owner、发布状态、scene 版本和最新尝试，校验通过后才写入场景。旧任务晚返回、场景已编辑或删除、任务已取消、图片已被新任务替代时，候选保留供核对，但不能覆盖当前作品。发布后的故事板不能被后续图片完成回写降级。

同步供应商请求在发出后遇到超时或网络错误时标记为 `reconciliation_required`，自动重试接口返回冲突，不再次调用付费供应商。已有候选 URL 的失败任务直接从本地候选恢复；活跃任务只继续等待；当前 scene 没有任何历史任务时才允许创建新的图片任务。

## iOS 交互

碎片和故事板统一使用恢复卡片、已有成果卡和 44pt 操作按钮。恢复、保存选择及取消确认期间禁用重复操作。取消只有在后端确认后才退出生成态；失败或暂停时保留正文和已生成页面。故事板页按 scene ID 和最新尝试映射图片，不压缩缺图位置，避免后续编辑错页；缺页时发布按钮保持禁用。

## 发布边界

本次包含碎片任务的 lease/checkpoint 数据库列和 [可重复执行的 MySQL 迁移脚本](../scripts/fragment_task_execution_20261023.sql)。发布前必须准备 schema 并使旧生成进程退出，不能让不支持 fencing 的旧二进制与新 worker 同时执行。已存在的无检查点任务不能凭空补齐模型结果。

本次验证使用本地数据库、mock 和 iOS 离线 fixture，不调用真实模型、不扣费、不迁移运行中的数据库、不重启或部署服务。实际进程强杀、MySQL 多实例接管、真实供应商对账和真实余额变化仍需在隔离环境验收。

已通过 `go test ./internal/... -count=1`、iOS `build-for-testing`、CreationRecovery/碎片解码/故事板修订单测，以及碎片和故事板两组共 22 个 UI 场景。回归覆盖并发唯一领取、账本幂等、失租写入拒绝、断点复用、未知结果停止、提交后恢复不重复追加、候选图事务接纳、发布防降级、历史请求编号重试、HTTP 409、失败成果保留、恢复锁定、取消确认和选页编辑。数据库并发测试使用本地 SQLite，不替代真实 MySQL 多实例验收。
